# 职业探索 Agent — PRD & 技术方案

> 版本: v1.0 | 日期: 2026-08-08 | 状态: 待评审

---

## 一、产品概述

### 1.1 产品定位

一款面向 6-12 岁儿童的 H5 职业探索体验。用户通过"翻卡"随机抽取一个职业，查看该职业的图文介绍，然后通过 5 步左右的小游戏任务沉浸式体验该岗位的工作内容，最后获得相关实践资源推荐。

### 1.2 核心价值

- **低门槛探索**：翻卡机制降低选择焦虑，随机性带来惊喜感
- **沉浸体验**：不是"看资料"，而是"做任务"——通过模拟工作流理解职业
- **行动闭环**：不仅了解职业，还能获得书单/营地/参观等"下一步行动"指引

### 1.3 MVP 范围

- 先做 **1 个职业（航天员）** 的完整链路跑通
- H5 单页原型，无后端
- 纯前端静态资源部署

## 二、产品流程

### 2.1 整体用户旅程

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│ ① 翻卡   │───→│ ② 介绍   │───→│ ③ 体验   │───→│ ④ 推荐   │
│ 随机抽取  │    │ 图文展示  │    │ 小游戏   │    │ 资源推荐  │
└──────────┘    └──────────┘    └──────────┘    └──────────┘
   30秒            2-3分钟         3-5分钟         1-2分钟
```

### 2.2 环节一：翻卡

**交互描述**：
- 用户看到一张背面朝上的卡片（深色底 + 金色问号 + "职业探索"字样）
- 点击卡片 → 3D 翻转动画 → 显示职业正面（emoji + 职业名称 + 一句话 tagline + 关联学科标签）
- 翻卡结果随机从职业池中抽取

**设计要点**：
- 背面保持神秘感，问号用金色突出
- 翻转动画约 0.8s，使用 CSS 3D transform 或 Three.js
- 翻完后短暂停留（1.5-2s），自动过渡到介绍环节
- 每张卡正面绑定一个历史/现代人物形象（如航天员 → 可以绑定杨利伟/阿姆斯特朗），增强故事感

**待填充内容**：
- 每个职业绑定的人物形象（名称 + 简短介绍）

### 2.3 环节二：介绍（H5 图文）

**交互描述**：
- 翻卡完成后进入职业介绍页
- 以大卡片/H5 长图文形式展示

**内容结构（4 个模块）**：

| 模块 | 内容 | 展示形式 |
|------|------|---------|
| (a) 基础信息 | 职业名称、所属领域、平均薪资范围、学历门槛、相关学科 | 标签 + 数据卡片 |
| (b) 需要特质与能力 | 6-8 项核心能力 + 每项一句话说明 + 反面案例 | 能力卡片网格 |
| (c) 工作内容 | 典型的一天时间线 / 核心任务描述 | 时间轴 + 场景插图 |
| (d) 典型人物 | 1-2 位该领域代表人物 + 简短故事 | 人物卡片 |

**交互**：
- 底部有"感兴趣度"星级评分（1-5⭐）
- ≥3⭐ → 显示"进入体验"按钮
- <3⭐ → 显示"再翻一张"按钮

**待填充内容**：
- 每个职业的 4 个模块具体文案（用户后续提供）

### 2.4 环节三：体验（小游戏）

**交互描述**：
- 5 步左右的连续小任务，模拟该职业的核心工作流
- 每步有场景说明 + 交互操作 + 即时反馈

**任务设计原则**（参考 [能力模型到工作流的方法论](./能力模型到工作流的方法论.md)）：
- 保留决策，删除执行
- 保留分支，压缩线性
- 保留反常，删除常规
- 每步锻炼 1-2 个核心能力
- 包含至少 2 个"情感峰值"（自主决策 + 成就感时刻）

**交互类型池**：

| 交互类型 | 适合场景 | 示例 |
|---------|---------|------|
| `choice` | 方案决策、风险判断 | A/B 方案选择 |
| `drag` / `sort` | 精密执行、流程排序 | 零件归位 / 步骤排序 |
| `checklist` | 风险检查、系统思维 | 发射前检查清单 |
| `countdown` | 压力决策 | 倒计时 + 突发状况 |
| `dialog` | 信息传递、引导 | 导师对话/任务说明 |

**能力雷达图**：
- 体验结束后，根据用户在每个任务的表现生成六维能力雷达图
- 给出匹配度总分 + 1-2 句个性化评语

**待填充内容**：
- 每个职业的 5 步任务具体内容（用户后续提供）

### 2.5 环节四：推荐

**内容结构**：

| 推荐类型 | 内容 | 示例 |
|---------|------|------|
| 🏕️ 实践机会 | 所在城市的相关夏令营/体验活动 | "北京航天科普夏令营" |
| 📚 科普书单 | 3-5 本适合该年龄段的入门书籍 | 《下一站火星》《太空旅行指南》 |
| 🎯 体验参观 | 可参观的场馆/基地 | "中国科学技术馆·太空探索厅" |

**待填充内容**：
- 每个职业的推荐资源列表（用户后续提供）

## 三、设计风格与视觉规范 🎨

> **设计原则**：Apple 的"简洁与克制"做骨架，儿童友好的"温暖与趣味"做血肉。
> 目标用户 6-12 岁，需要在高级感和亲和力之间取得平衡——不能让家长觉得"廉价"，也不能让孩子觉得"高冷"。

### 3.1 设计哲学：三句话

| 原则 | 说明 |
|------|------|
| **像积木一样清晰** | 每个元素圆润、大块、边界清楚。儿童能一眼识别"这是什么、可以点" |
| **像绘本一样温暖** | 色彩柔和但不寡淡，有童话般的梦幻感。圆形、弧线为主，避免尖锐直角 |
| **像游戏一样有趣** | 每次点击都有反馈，每个过渡都有动画。失败不是惩罚，而是"再来一次"的邀请 |

### 3.2 色彩体系

#### 主色调：星空童话

摒弃暗黑科技风，走"梦幻星空绘本"路线——深色底保留太空主题的神秘感，但用暖色点缀和柔光过渡让它变得温柔。

```
深色底（保留太空感）           点缀色（温暖 + 趣味）
┌─────────────────────┐      ┌─────────────────────┐
│ 深邃紫蓝 #1a1a3e    │      │ 暖金色   #ffb74d    │ ← 主要 CTA、星级、高亮
│ 深空蓝   #16213e    │      │ 珊瑚粉   #ff8a80    │ ← 庆祝、成功反馈
│ 午夜蓝   #0f0f2d    │      │ 薄荷绿   #69f0ae    │ ← 正确、通过
│ 卡片底   rgba(...)  │      │ 天空蓝   #64b5f6    │ ← 信息、标签
│ 毛玻璃   blur(24px) │      │ 薰衣草紫 #ce93d8    │ ← 魔法感、特殊
└─────────────────────┘      └─────────────────────┘

渐变主按钮：linear-gradient(135deg, #ffb74d, #ff8a80)  ← 暖金 → 珊瑚
渐变次按钮：linear-gradient(135deg, #64b5f6, #ce93d8)  ← 天空 → 薰衣草
```

#### 功能色语义

| 颜色 | 用途 | 儿童友好语义 |
|------|------|------------|
| 🟡 暖金 | 主按钮、星级、成就 | "点这里！有好东西！" |
| 🟢 薄荷绿 | 正确反馈、进度完成 | "太棒了！做对了！" |
| 🔴 珊瑚粉 | 错误反馈（不用纯红） | "差一点点，再试试！" |
| 🔵 天空蓝 | 信息标签、学科 chip | "了解这些知识" |
| 🟣 薰衣草紫 | 魔法/特殊交互 | "这里藏着惊喜！" |

### 3.3 字体与排版

| 层级 | 大小 | 字重 | 用途 |
|------|------|------|------|
| 英雄标题 | 32-40px | Bold (700) | 职业名称、结果页分数 |
| 模块标题 | 22-26px | Semibold (600) | 介绍模块标题、任务标题 |
| 正文 | 16-18px | Regular (400) | 描述文字、对话框 |
| 辅助文字 | 13-14px | Regular (400) | 标签、提示、进度指示 |
| 数字/分数 | 48-56px | Bold (700) | 能力分数、匹配分 |

- **字体**：系统默认中文字体（PingFang SC / 苹方），数字用 SF Pro Display / DIN
- **行距**：正文 1.8-2.0（宽松，适合儿童阅读）
- **对齐**：标题居中，正文左对齐
- **emoji 使用**：大量使用 emoji 作为视觉锚点（图标、标签、反馈），6-12 岁儿童对 emoji 识别度高

### 3.4 形状与圆角

```
圆角规则（越面向儿童越大）：
┌────────────────────────────────────────┐
│ 按钮      r=16px  (全圆角胶囊感)        │
│ 卡片      r=24px  (大圆角，像绘本翻页)    │
│ 标签 chip r=20px  (胶囊形)              │
│ 弹窗      r=28px  (接近圆形)            │
│ 进度条    r=8px   (圆头)                │
│ 图标容器  r=50%   (正圆形)              │
└────────────────────────────────────────┘

🚫 避免：直角矩形、锋利边缘、细线条
✅ 推荐：圆角矩形、胶囊形、圆形、柔和阴影
```

### 3.5 动效规范

#### 缓动曲线

```css
/* Apple 式平滑 — 用于页面过渡、卡片出现 */
--ease-apple: cubic-bezier(0.25, 0.1, 0.25, 1.0);

/* 弹性回弹 — 用于按钮点击、元素弹出、庆祝 */
--ease-bounce: cubic-bezier(0.34, 1.56, 0.64, 1);

/* 玩趣弹跳 — 用于 emoji 动画、角色入场 */
--ease-playful: cubic-bezier(0.68, -0.55, 0.265, 1.55);
```

#### 关键动效时长

| 动效 | 时长 | 曲线 | 说明 |
|------|------|------|------|
| 卡片翻转 | 800ms | apple | 翻转轴心在卡片中央 |
| 页面过渡 | 400ms | apple | 淡入 + 上移 12px |
| 按钮按压 | 150ms | bounce | scale 1→0.95→1 |
| 元素弹入 | 500ms | playful | 列表项逐个出现 (stagger 80ms) |
| 正确答案 | 400ms | bounce | 缩放弹跳 + 粒子散开 |
| 错误提示 | 300ms | apple | 左右摇晃 2 次 (shake) |
| 进度填充 | 800ms | apple | 从左到右填充 |
| 星星点亮 | 300ms/颗 | bounce | 依次点亮，每颗间隔 150ms |

#### 微交互库

| 交互 | 实现 | 触发条件 |
|------|------|---------|
| 悬浮放大 | `scale(1.05)` + 阴影加深 | 桌面端 hover |
| 按压缩小 | `scale(0.95)` | 移动端 touch |
| 涟漪扩散 | 从触点扩散的圆形波纹 | 按钮点击 |
| 粒子爆发 | ⭐✨💫 向四周飞散 | 任务完成、成就解锁 |
| 弹跳 | `translateY` 上下弹跳循环 | 可点击提示、未读提醒 |
| 摇头 | 左右旋转 ±5deg | 错误操作反馈 |

### 3.6 玻璃态卡片规范（Apple 风格继承）

```
glass-card {
  background: rgba(20, 18, 50, 0.75);    /* 深紫底 + 半透明 */
  backdrop-filter: blur(24px);            /* Apple 毛玻璃 */
  border: 1px solid rgba(255,255,255,0.12);
  border-radius: 24px;                    /* 大圆角 */
  box-shadow:
    0 8px 32px rgba(0,0,0,0.2),          /* 外层柔和阴影 */
    0 0 0 1px rgba(255,255,255,0.05),    /* 内发光边缘 */
    inset 0 1px 0 rgba(255,255,255,0.08); /* 顶部高光线 */
}
```

### 3.7 面向 6-12 岁儿童的交互设计准则

| 准则 | 说明 | 实现 |
|------|------|------|
| **大触控区** | 可点击元素最小 48×48px | 按钮 padding ≥ 14px |
| **即时反馈** | 每次操作 100ms 内给予视觉/听觉反馈 | 按压态 + 音效（可选）|
| **容错设计** | 没有"不可挽回"的操作，所有选择可重来 | 返回按钮 + 重试按钮 |
| **正向鼓励** | 错了吗？没关系！"差一点点，再试试看！" | 珊瑚粉反馈 + 鼓励文案 |
| **进度可见** | 始终知道"我在哪、还有几步" | 步骤指示器 (1/5, 2/5...) |
| **成就可视化** | 每完成一步都有明确的"完成感" | 勾选动画 + 粒子 + 音效 |
| **减少文字** | 多用图/emoji/动画，少用长段落 | emoji 标签 + 插图 + 对话框 |

## 四、3D 场景与交互动画规范 🪐

> **核心目标**：为 6-12 岁儿童打造一个"像动画片一样好看、像积木一样好操作"的 3D 世界。
> 3D 不是炫技，而是营造沉浸感和空间趣味——让孩子感觉"我真的在太空舱里"。

### 4.1 3D 场景设计原则

| 原则 | 说明 |
|------|------|
| **低多边形卡通风格 (Low-Poly Cartoon)** | 圆润的几何体、柔和的材质，像《纪念碑谷》或皮克斯短片，不像《星际穿越》 |
| **玩具感 > 真实感** | 火箭像大玩具、星球像弹珠、太空舱像树屋——让场景像孩子的玩具间 |
| **色彩鲜艳但不刺眼** | 饱和度高但不荧光，柔光漫反射，全局暖色调打底 |
| **场景小而精** | 不做宏大宇宙，做一个"桌面上的太空世界"——焦点场景直径约 2-3 米 |

### 4.2 各阶段 3D 场景详细设计

#### 阶段一：大厅（Hall）—— 星空桌面

```
┌─────────────────────────────────────────┐
│                                         │
│     ✦ ✦ ✦ 缓慢旋转的星星粒子 ✦ ✦ ✦      │
│                                         │
│         🪐 一颗大大的卡通星球             │
│         (缓慢自转，暖色柔光)              │
│                                         │
│     ╔══════════════╗                    │
│     ║   🚀  ?     ║ ← 3D 卡片悬浮       │
│     ║   职业探索   ║   缓慢上下浮动       │
│     ╚══════════════╝                    │
│                                         │
│   🌙 小卫星环绕   ⭐ 流星偶尔划过         │
│                                         │
└─────────────────────────────────────────┘

相机：固定视角，略俯视（15°），距离约 3m
光照：暖色环境光 (0.6) + 金色点光源从右上方打来 + 星球边缘柔光
动画：星球自转 (0.1 rad/min)，粒子缓慢上升，卡片上下浮动 ±15px
粒子：200-300 个小星点 (SphereGeometry r=2-6)，随机分布在场景中，
      缓慢旋转上升，带微弱的发光材质 (MeshStandardMaterial emissive)
```

#### 阶段二：翻卡（Draw）—— 卡片翻转

```
动画序列：
0ms     卡片背面（金色问号）静止
0-200ms 卡片放大 scale(1→1.08)，"被按下"的反馈
200ms   开始绕 Y 轴翻转，同时轻微上浮
400ms   卡片垂直于视线（侧面看是一条线），此时出现金色粒子环绕
600ms   卡片正面开始显现
800ms   翻转完成，卡片轻微弹跳 (bounce)，emoji 放大弹出
1000ms  粒子散开，学科标签依次弹入

3D 实现：
- CSS 3D Transform (preserve-3d + rotateY) 做卡片翻转
- 翻转过程中卡片边缘 glow 发光 (box-shadow 动画)
- 完成后正面的 emoji 有 scale(0→1.2→1) 弹性动画
```

#### 阶段三：介绍（Reveal）—— 场景切换

```
翻卡完成后，3D 场景从"大厅"过渡到"职业主题场景"

航天员主题场景：
┌─────────────────────────────────────────┐
│                                         │
│   🚀 卡通火箭 (1/3 画面)                  │
│   发射台上，微微冒烟，引擎发光             │
│                                         │
│   ┌──────────────────────┐              │
│   │  介绍卡片（毛玻璃）     │              │
│   │  👨‍🚀 航天员           │ ← 2D UI 覆盖  │
│   │  基础信息 / 能力 ...   │              │
│   └──────────────────────┘              │
│                                         │
└─────────────────────────────────────────┘

相机：从大厅平滑过渡 (lerp)，视角微调至更侧面的角度
场景元素：
  - 火箭模型（低多边形，主色白+暖金点缀）
  - 发射台（六边形底座，科技蓝发光边）
  - 地面：浅灰色网格，像设计图/蓝图风格
  - 背景：柔和的蓝紫渐变天空，比大厅更亮
```

#### 阶段四：体验（Experience）—— 每步场景切换

```
5 步任务对应 5 个迷你场景，每个场景是一个"舞台"

Step 1 训练中心 → 室内场景，跑步机+体能测试仪器（玩具化）
Step 2 模拟器舱 → 控制面板特写，按钮/旋钮/屏幕（可交互）
Step 3 发射倒计时 → 火箭+发射塔，警报灯闪烁
Step 4 太空舱内  → 圆形舷窗看到地球，舱内仪表盘
Step 5 返回着陆   → 降落伞+着陆点，庆祝粒子

场景切换动画：
- 相机拉远 → 平移 → 推进 (dolly-zoom 风格)
- 旧场景元素下沉消失，新场景元素从上方降下
- 过渡时长 600ms，缓出缓入

每个场景的元素数量控制在 5-10 个以内，保持"舞台剧布景"的简洁感
```

#### 阶段五：结果（Result）—— 庆祝舞台

```
体验完成后的庆祝场景：

│                                         │
```

### 4.3 3D 材质与光照规范

#### 材质风格

```
统一使用卡通/玩具材质：

MeshToonMaterial       ← 首选：色阶着色，像 cel-shading
  color: 主体色
  gradientMap: 3 阶渐变纹理

MeshStandardMaterial   ← 次选：金属/发光部件
  roughness: 0.3-0.6   (不要太光滑，保持哑光质感)
  metalness: 0-0.3     (低金属度，保持柔和)
  emissive: 用于发光部件（引擎、屏幕、星星）
```

#### 光照配方

```typescript
// 三灯布光法（经典人像光，让物体立体但不锐利）
const lightingSetup = {
  ambient:   { intensity: 0.6, color: '#fff5ee' },  // 暖色环境光，消除死黑
  key:       { intensity: 0.8, color: '#ffffff', position: [5, 8, 5] },  // 主光：右上方
  fill:      { intensity: 0.3, color: '#b3d4ff', position: [-3, 2, -2] }, // 补光：左下方，淡蓝
  rim:       { intensity: 0.4, color: '#ffd54f', position: [0, 2, -5] },  // 轮廓光：后方，暖金
};

// 场景总基调
scene.fog = new THREE.Fog('#16213e', 8, 25);  // 远淡蓝雾，营造景深感
```

### 4.4 3D 交互规范（6-12 岁适配）

| 规范 | 说明 | 技术实现 |
|------|------|---------|
| **自动旋转，不必手动** | 3D 物体自动缓慢旋转展示，不强制要求拖拽旋转 | `useFrame` 中缓慢自转 |
| **可选的手势控制** | 如果孩子在触屏上拖拽，可以旋转视角；不拖就自动转 | OrbitControls, `enableRotate: true`, `autoRotate: true` |
| **大 hitbox** | 3D 可点击物体周围有不可见的扩大碰撞区 | `Raycaster` + 扩大判断半径 1.5 倍 |
| **点击高亮** | 3D 物体被点击时，短暂发光 + 缩放弹跳 | `emissive` 属性动画 + `scale` tween |
| **拖拽吸附** | 拖拽 3D 零件时，接近目标位置自动吸附 (snap) | 距离 < 阈值 → `lerp` 到目标位置 |
| **相机不晃** | 相机移动平滑，无突然加速/减速 | 所有相机运动用 `lerp`，factor 0.08 |
| **不晕 3D** | FoV 固定 50°，不做广角，不快速旋转 | 禁用 `damping` 过大值 |

### 4.5 3D 性能预算（移动端优先）

| 指标 | 目标 | 说明 |
|------|------|------|
| 三角面总数 | < 15,000 | 低多边形风格天然满足 |
| Draw calls | < 30 | 合并同类材质，使用 InstancedMesh |
| 纹理总大小 | < 2MB | Canvas 程序化生成纹理为主，不用大贴图 |
| 帧率 | ≥ 30fps (中端手机) | 使用 `mobile` 预设降低特效 |
| 首屏加载 | < 3s | Three.js CDN + 代码分割 |
| 粒子数量 | < 300 | 超过 300 在低端机掉帧 |

### 9.1 游戏产品设计专家审查

#### 🔴 问题一：感兴趣度评分的位置打断了心流

**现状**：翻卡 → 看完介绍 → 弹出 1-5⭐ 评分 → ≥3⭐ 才给进入体验。

**问题**：这是成人产品的 UX 模式（评价 → 决策）。儿童刚被职业吸引，正处于"哇！火箭好酷！"的情绪高点，突然被要求"打分"，认知切换太突兀。而且对 6-8 岁儿童，"打分"这个概念本身就抽象。

**建议**：
```
翻卡 → 介绍 → [大按钮]"想试试当一天航天员吗？🚀" → 直接进入体验
                                    ↓
                              不感兴趣 → "换一张卡！"
```
- 用行动替代评价：**想 = 点按钮进入，不想 = 换一张**
- 评分/感兴趣度移至体验结束后，与能力报告一起呈现，作为"自我反思"而非"准入门槛"

#### 🔴 问题二：单职业 MVP 下"随机翻卡"无意义

**现状**：翻卡随机抽取，但 MVP 只有 1 个职业。

**问题**：每次都翻到同一张卡，儿童很快会发现"骗人的随机"，失去惊喜感——而这个环节本应是整个体验的 Hook。

**建议（三选一）**：
| 方案 | 做法 | 工时 |
|------|------|------|
| A | 再加 2 个"轻量职业"（只需卡片+介绍，体验暂时"敬请期待"） | +1天 |
| B | 单职业模式下隐藏"随机翻卡"，改为"神秘卡片 → 点击揭晓"的叙事 | 0 |
| C | 加 3-4 张占位卡，翻到"未解锁"时引导回航天员 | +0.5天 |

**推荐 B（MVP 最快）或 A（体验最好）**。

#### 🟡 问题三：缺少叙事钩子和引导角色

**现状**：用户打开页面 → 看到一张卡片 + 问号。6 岁孩子可能不知道要干嘛。

**建议**：引入一个**固定向导角色**（如一只卡通猫头鹰 🦉"小知"），贯穿全流程：
- 开场："嗨！我是小知！这里藏着好多神奇的职业卡片，点一下试试看？"
- 介绍环节：小知在旁边补充趣味知识
- 体验环节：小知化身为"任务发布官"
- 错误时：小知鼓励"没关系，我告诉你一个小秘密…"

> 这不仅是 UX 改善，也是**情感锚点**——儿童对角色产生依恋，愿意反复回来。

#### 🟡 问题四：缺少收集系统和回访动力

**建议**：增加"职业收藏册"概念——每体验一个职业，收藏册里点亮一张卡。大厅展示"已发现 1/12"，激发收集欲。这是 6-12 岁儿童最自然的游戏动机。

#### 🟡 问题五：任务流程完全线性，缺少分支感

**现状**：5 步任务所有人体验完全相同。

**建议**：在 Step 3（发射倒计时）引入一个真正的分支——如果选择"中止发射"，后续 Step 4-5 变成"故障排查 → 重新发射"而不是"在轨实验 → 返回"。**只需 1 个分支点**，重玩价值翻倍。

### 9.2 游戏开发专家审查

#### 🔴 问题一：CSS 3D 翻卡 + Three.js 场景混用的技术风险

**现状**：翻卡用 CSS `preserve-3d + rotateY`，场景背景用 Three.js Canvas。

**问题**：两个渲染上下文叠在一起时，在移动端 Safari 上会出现严重的合成器冲突（compositor fighting）——卡片翻转时，背景 Canvas 可能闪烁或暂停渲染。z-index 和 `transform` 创建了不同的合成层，iOS WebKit 对此处理尤其糟糕。

**建议**：
```
统一到 Three.js (R3F)：
  - 卡片翻转用 Three.js 的 mesh.rotation.y 动画
  - 卡片正反面用两个 Plane Mesh 背靠背放置
  - 翻转时直接旋转整个 Card Group
  
优势：
  - 单一渲染上下文，无合成冲突
  - 卡片翻转时的金色粒子可以用 Three.js Particles
  - 翻转过程中相机可以做微妙的 dolly，增强 3D 感
```

#### 🔴 问题二：5 个不同 3D 场景在移动端的加载策略缺失

**现状**：体验阶段 Step 1-5 各有一个完全不同的 3D 场景。

**问题**：如果每个场景切换时要加载新的几何体/纹理，在 4G 网络上会有明显白屏。预加载所有场景又超出移动端内存预算。

**建议**：
```
方案：单一场景 + 模块化道具

构建一个"舞台"基场景（地板 + 灯光 + 天空盒），Step 1-5 只更换道具：
  Step 1: base + 跑步机模型 + 体能测试仪器
  Step 2: base + 控制台模型 + 按钮组
  Step 3: base + 火箭模型 + 警报灯
  ...

道具策略：
  - 所有道具在 Hall 阶段后台预加载（用户看介绍时）
  - 道具切换用 opacity 0→1 渐变 (300ms)，无需卸载
  - 单个道具 geometry 合并，减少 draw calls
  - 道具总数控制在 20 个以内
```

#### 🟡 问题三：Canvas 2D 纹理生成的视觉天花板

**现状**：`textureGenerator.ts` 用 Canvas 2D API 程序化生成卡片和地球纹理。

**问题**：Canvas 2D 只能画简单几何形状。用 ellipse/fillRect 画的"地球"和"火箭"效果非常粗糙——这在 prototype 阶段 OK，但面向儿童的产品视觉要求高。

**优化方案**（设计视角）：

**思路**：拥抱"手工感"——把限制变成风格。儿童的绘本不是照片级渲染，而是**插画风格**。用 SVG + 噪声算法生成"手绘感"纹理，比强行写实更高级。

```
方案："三层纹理策略"——不同物体用不同生成方式

第一层：Canvas 渐变纹理（用于纯色/渐变物体）
  适用：卡片、UI 面板、简单几何装饰
  方法：Canvas2D 线性/径向渐变 + 少量噪声打破完美渐变
  效果：像水彩纸的纹理质感

第二层：SVG → Canvas → Texture 管线（用于"需要画出来"的物体）
  适用：星球表面、星座连线、装饰图案
  方法：
    1. 用 SVG 画矢量图（圆形、路径、星座线、环形山）
    2. 在 SVG 里加 <filter> 添加噪点/粗糙边缘（模拟手绘感）
    3. 用 Canvas 把 SVG 渲染为纹理
    4. 传给 Three.js Texture
  优势：
    - SVG 矢量 → 多大分辨率都清晰
    - SVG filter 可实现"蜡笔质感""水彩边缘"
    - 文件体积极小（一段 XML 字符串，通常 < 2KB）
  示例——一个"弹珠星球"的 SVG：
    <svg viewBox="0 0 256 256">
      <defs>
        <radialGradient id="g">...</radialGradient>
        <filter id="paper">
          <feTurbulence type="fractalNoise" baseFrequency="0.04"/>
          <feColorMatrix type="saturate" values="0"/>
          <feBlend in="SourceGraphic" mode="multiply"/>
        </filter>
      </defs>
      <circle r="120" fill="url(#g)" filter="url(#paper)"/>
      <!-- 环形山：几个更小的圆 -->
      <circle cx="-30" cy="-20" r="18" fill="rgba(0,0,0,0.08)"/>
      <circle cx="40" cy="30" r="12" fill="rgba(0,0,0,0.06)"/>
    </svg>

第三层：Three.js 内置几何体拼装（用于不需要纹理的物体）
  适用：火箭、发射台、太空舱、控制面板
  方法：
    - 火箭身体 = CylinderGeometry + 顶部 ConeGeometry + 底部三个小 Cylinder（推进器）
    - 用 MeshToonMaterial 给每个部分上纯色，靠几何体拼接出细节
    - 不需要任何贴图
  效果：
    - 像高质量的积木玩具（LEGO 感）
    - 纯色 + Toon 着色器自带"卡通描边"效果
    - 完全不需要纹理加载，零体积

总结：
  ┌──────────────┬──────────────────┬──────────┐
  │ 物体类型      │ 纹理生成方式      │ 风格参考   │
  ├──────────────┼──────────────────┼──────────┤
  │ 卡片、面板    │ Canvas 渐变+噪声  │ 水彩纸质感  │
  │ 星球、星座    │ SVG+Filter→Canvas│ 绘本插画    │
  │ 火箭、设备    │ 纯几何体拼装      │ 积木玩具    │
  │ UI 图标/emoji│ 原生 emoji/CSS   │ 系统原生    │
  └──────────────┴──────────────────┴──────────┘
```

#### 🟡 问题四：移动端触摸的特殊性被低估

**额外需要处理的情况**：
- **手掌误触**：儿童握 iPad 时手掌边缘会触发 touch 事件 → 需要 palm rejection（通过 `touch.radiusX/Y` 判断）
- **多点同时触摸**：另一只手误触屏幕 → 只响应第一个 touch point
- **长按 vs 点击**：儿童按住时间更长（平均 400-600ms vs 成人 200ms）→ 把点击判定窗口放宽到 500ms
- **iOS AudioContext 锁定**：首次用户手势才能解锁 Web Audio API → Loading 页的"点击开始"按钮同时解锁音频

#### 🟡 问题五：状态恢复机制缺失

**建议**：在 store 中增加 `sessionResume` 能力——如果儿童关闭浏览器时正在 Step 3，下次打开时小知问："上次你在发射火箭呢！继续吗？"

### 9.3 儿童教育专家审查

#### 🔴 问题一：6-12 岁年龄跨度过大，需分龄设计

**现状**：整个产品面向"6-12 岁"，内容复杂度、交互方式、文字量未区分。

**问题**：

| 维度 | 6-8 岁（小学低段） | 9-12 岁（小学高段） |
|------|-------------------|---------------------|
| **阅读能力** | 识字量 800-1600，需要拼音辅助 | 识字量 2500+，可独立阅读短段落 |
| **认知阶段** | 具体运算期：需要具象、可操作的内容 | 形式运算萌芽：开始理解抽象概念 |
| **注意力** | 8-15 分钟单任务 | 20-30 分钟 |
| **动机来源** | 外部：好玩、好看、被夸奖 | 内部萌芽：我想知道"为什么" |
| **数字概念** | 能理解"大/小""多/少"，不理解"85分" | 能理解分数、百分比、排名 |

**建议**：
```
MVP 阶段：默认走 9-12 岁标准（当前文档的文字量/交互复杂度基本匹配）
但需要为 6-8 岁做"简化开关"：

简化模式变化：
  - 大段文字 → 拆成单句对话框，逐句出现
  - "能力雷达图" → "你最厉害的三件事"（三枚徽章）
  - "85分" → "⭐⭐⭐⭐ 太棒了！"
  - 倒计时 → 无时间限制
  - 反面案例 → 改为"有趣的小插曲"
```

#### 🔴 问题二："反面案例"对低龄儿童不适用

**现状**：(b) 特质与能力模块包含"反面案例"。

**问题**："反面案例"在原有方法论中是面向 12-18 岁的，对 6-12 岁需要重新定义。尤其航天领域的事故（挑战者号、哥伦比亚号）涉及伤亡，引用这些对 6-10 岁儿童可能造成恐惧。

**建议**：
- **6-8 岁**：取消"反面案例"。改为"你知道吗？"趣味知识（"你知道吗？在太空里，航天员长高 5 厘米！因为脊椎没有重力压着"）
- **9-12 岁**：保留反面案例，但用**模拟场景而非真实事故**（"如果忘记检查氧气阀门，模拟器里会…"）

#### 🟡 问题三：intro.md 中的"薪资""学历"对儿童无意义

**现状**：基础信息包含"平均薪资""学历门槛"。

**建议**：替换为儿童能理解的维度：
```
Before（成人向）                 After（儿童向）
─────────────────────────────────────────────
平均薪资：XXX                    ❌ 删除
学历门槛：本科及以上               → "需要学习多久：至少 16 年"
所属领域：航天航空                 → "工作地点：太空！🌍→🚀"
关联学科：物理、数学...            → ✅ 保留，加趣味说明
                                → 🆕 "一天中最酷的事：在太空看日出（一天看16次！）"
                                → 🆕 "工具箱里有什么：太空服、机械臂、实验器材"
```

#### 🟡 问题四：缺少教育目标定义

**优化方案**（设计视角）：

**思路**：不要让"学习目标"像考纲一样贴在开头——而是把目标隐藏在**体验后的发现时刻**。

```
方案："今天我发现了…"——体验结束后的 3 张发现卡

体验结束后，不是显示能力分数，而是依次翻开的 3 张"发现卡"：

┌──────────────────────┐

│                      │
│  这就是"精密执行"能力   │

┌──────────────────────┐
│  💡 发现三            │
│                      │

│  重复练习             │
│                      │
│  厉害的人不是天生厉害   │

设计意图：
  - 发现卡 = 学习目标的"故事化"呈现
  - 不出现"学习目标"这个词，但每张卡对应一个知识点
  - 翻卡揭晓的交互呼应开头，形成闭环
  - 最后一张卡（发现三）是"成长心态"的植入：能力是练出来的

数据层实现：
  interface Career {
    // ... existing fields
    discoveries: DiscoveryCard[];  // 3 张体验后的发现卡
  }

  interface DiscoveryCard {
    emoji: string;
    title: string;      // "航天员在太空每天看到 16 次日落！"

    bigIdea: string;    // 隐含的大概念："精密执行""成长心态"等

家长视角（资源推荐页附带的"家长小贴士"）：
  "您的孩子今天通过航天员体验：
   🧠 锻炼了快速反应和系统思维
   📖 了解了太空环境的基本常识
   💪 感受到'反复练习才能成功'的成长心态
   
   延伸对话建议：问问孩子'如果你是航天员，你最想在太空做什么实验？'"
```

#### ✅ 做得好的地方
- 推荐环节（实践/书单/参观）→ 将数字体验与真实世界连接，非常有教育价值
- 能力雷达图 → 比"对/错"更能体现多元智能
- 5 种交互类型 → 覆盖了不同类型的认知锻炼

### 9.4 儿童心理专家审查

#### 🔴 问题一：数字评分可能引发表现焦虑

**现状**：体验结束后给出"85分"、星级、能力分数。

**问题**：8-12 岁是**社会比较敏感期**——孩子开始用数字衡量自己。一个"65分"可能被解读为"我不适合当航天员"，而我们的本意是"可以多了解"。

**建议**：
```
取消数字分数，改用"角色徽章"系统：

不是：你得了 85 分 ⭐⭐⭐⭐
而是：你获得了【火箭指挥官】徽章！🚀
      你在"快速反应"上表现特别棒——发射倒计时时你冷静地做出了正确判断！

每个孩子都会获得 1-2 个正面徽章（基于他们实际表现最好的维度）
徽章体系让每个人都有"赢"的体验，而不是被数字排序
```

#### 🔴 问题二：倒计时时间压力对 6-8 岁是焦虑源

**现状**：Step 3 发射倒计时 + 突发警报决策。

**问题**：时间压力对低龄儿童触发的是**应激反应**而非"刺激感"。6-8 岁的前额叶皮层尚未发育完全，在时间压力下的决策能力显著低于成人。倒计时可能让他们紧张到随机乱点，而不是享受挑战。

**建议**：
- **6-8 岁模式**：倒计时改为"慢慢来"——没有真实时间限制，只是在视觉上展示数字跳动，孩子可以想多久就多久。警报出现时小知跳出来说："别急，我们一起看看到底怎么回事？"
- **9-12 岁模式**：保留时间限制，但设置得宽松（30 秒而非 10 秒），倒计时数字用暖金色而非红色

#### 🟡 问题三：黑暗太空主题可能引发低龄儿童的恐惧

**现状**：全局深色底 (#1a1a3e, #0f0f2d)，太空场景。

**考虑**：深色背景 + 无限太空的意象，对少数 6-8 岁儿童可能触发轻微的**宇宙恐惧**（对无尽空间的焦虑）或**黑暗恐惧**。

**优化方案**（设计视角）：

**思路**：不靠"浅色模式切换"这种技术开关来解决——而是重新定义"太空"在儿童眼中的美学。儿童的太空不是《星际穿越》的深空，而是**绘本里的星空**。

```
方案："绘本星空"视觉体系

1. 背景不是"无尽虚空"，而是"故事书的夜空"
   - 底色从 #0f0f2d 调亮至 #1e1a40（保留紫色梦幻感，但更通透）
   - 天空中散布的不是随机星点，而是"星座连线图"——星星之间有淡淡的白色细线连接，像孩子们在图画书上看到的星座插图
   - 加入 1-2 朵淡淡的星云（暖粉/淡紫色模糊光团），像水彩画笔触

2. 星球不写实，而是"弹珠星球"
   - 像《小王子》里的星球——小小的、有表情的、色彩像糖果
   - 主星球用暖橙→粉色渐变，表面有可爱的环形山（圆润的凹陷，不尖锐）
   - 星球周围有白色虚线轨道环，卫星是更小的彩色球体

3. 🦉 向导角色自带"光源"
   - 小知猫头鹰总是蹲在场景左下角的一盏小灯笼旁边
   - 灯笼发出暖金色的柔和光晕，让孩子感觉"角落里有个温暖的朋友"
   - 这个光晕在技术上就是场景里的一个点光源（PointLight, warm color, small radius）

4. 场景过渡用"翻书页"隐喻
   - 不同场景切换不是相机飞行，而是像翻绘本——当前页掀起→下一页出现
   - 让孩子潜意识里知道：这是一个故事，不是真的被丢进了外太空
```

**效果对比**：
| 之前 | 之后 |
|------|------|
| 深黑太空背景，像电影截图 | 紫蓝夜空底色，像绘本插图 |
| 写实星球，灰蓝色调 | 弹珠星球，暖粉橘糖果色 |
| 随机粒子星点 | 星座连线图 + 水彩星云 |
| 孤独的 3D 空间 | 小知 + 灯笼始终陪伴 |

#### 🟡 问题四：缺少"安全出口"机制

**建议**：每个页面/阶段始终保留：
- **右下角**：🏠 回到大厅（固定位置，不随滚动消失）
- **体验环节**：跳过按钮（"我不想做这个任务"→ 小知帮忙完成，不扣分）
- **介绍环节**：语音朗读开关（对识字量不足的儿童至关重要）

> 心理安全的核心原则：**孩子应该感觉自己掌控着体验，而不是被体验推着走。**

#### 🟡 问题五：社交分享的"比较心理"风险与分享意愿不足

**现状**：分享卡片显示分数，可能引发攀比。且当前设计缺乏分享的"动机设计"。

**问题**：仅去掉分数还不够——需要回答"为什么家长/孩子会愿意分享？"分享不是功能，是**行为设计**。

**优化方案**（分享意愿视角）：

**思路**：把分享从"晒成绩"变成"晒身份"+"给家长一个行动入口"。分享的驱动力不是"看我多厉害"，而是"看我发现了什么"+"你也来试试"。

```
方案一："职业收藏卡"——像宝可梦卡牌一样的分享物

设计逻辑：
  - 每个职业是一张精心设计的"收藏卡"（类似球星卡/宝可梦卡的设计语言）
  - 卡片正面：职业 emoji（大）+ 职业名称 + 孩子获得的徽章名 + 一个"你知道吗？"冷知识
  - 卡片背面：能力画像（三星级，不是数字）+ 推荐资源 QR 码
  - 视觉风格：全息镭射质感（CSS gradient + 微妙的彩虹光泽）

为什么不显示分数：
  - 卡片上显示的不是"85分"，而是"🪐 星球探索者"这样的徽章名称
  - 所有完成体验的孩子都能获得徽章——每人的徽章基于最强维度生成，各不相同
  - 这让分享变成"你拿到了什么徽章？"而不是"你多少分？"

分享话术设计（预填文案，一键复制）：
  "我当了一天航天员🚀！我拿到了【星球探索者】徽章～
  你猜猜航天员在太空一天能看到几次日出？16次！🌅
  👉 [链接] 你也来发现你的职业超能力吧！"

方案二：分享的"双面卡"设计——孩子面 + 家长面

正面（孩子看）：
  ┌──────────────────────┐
  │   🚀 我当了           │
  │   一天航天员！         │
  │                      │
  │   🏅星球探索者        │
  │                      │
  │   "我在发射倒计时中    │
  │   做出了正确的判断！"   │
  └──────────────────────┘

背面（家长看，点击翻转）：
  ┌──────────────────────┐
  │   📋 家长视角          │
  │                      │
  │   您的孩子今天体验了    │
  │   航天员职业            │
  │                      │
  │   🧠 锻炼了：           │
  │   快速反应、系统思维     │
  │                      │
  │   📚 推荐资源：         │
  │   《下一站火星》        │
  │   北京航天科普夏令营     │
  │   [扫码查看完整书单]    │
  └──────────────────────┘

为什么这样设计：
  - 孩子的分享动机：炫耀徽章 + 让别人猜冷知识（互动性）
  - 家长的分享动机：获得实用的教育资源链接
  - 翻卡交互让分享本身也有"探索感"
  - 家长面把数字体验转化为真实世界的行动（买书/报营/参观）
```

**分享触发时机**：
- 不要在体验结束立刻弹"分享"——那时孩子还沉浸在成就感中
- 时机：**浏览推荐资源时**，底部出现"把这份资源清单发给爸妈 📤"
- 这是最自然的分享时机——不是"晒我多厉害"，而是"帮我安排这个！"

#### ✅ 做得好的地方
- "容错设计"和"正向鼓励"原则 → 对儿童心理健康非常友好
- 粒子爆发 + 庆祝动画 → 多巴胺正向反馈循环
- 推荐环节连接家长 → 将数字体验安全地延伸到现实
- "摇头"错误反馈而非弹窗警告 → 非惩罚性的纠错方式
